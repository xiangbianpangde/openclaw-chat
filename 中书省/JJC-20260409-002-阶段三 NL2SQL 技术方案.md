## 一、技术方案概述

### 1.1 架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    NL2SQL 引擎架构                       │
├─────────────────────────────────────────────────────────┤
│  用户自然语言 → 意图识别 → SQL 生成 → 查询执行 → 结果返回  │
│       ↓            ↓           ↓          ↓           ↓   │
│    "查营收"   财务查询   SELECT...   SQLite/    JSON/    │
│    "对比 Q1"   对比分析   FROM...     DuckDB    Markdown │
└─────────────────────────────────────────────────────────┘
```

**核心模块：**
1. **意图识别器**：分类用户查询类型（单值/对比/趋势/聚合）
2. **SQL 生成器**：基于微调模型生成 SQL
3. **查询执行器**：安全执行 SQL，返回结构化结果
4. **结果格式化**：转换为自然语言/表格/图表

## 二、模型选型方案

### 2.1 候选模型对比

| 模型 | 参数量 | 上下文 | 优势 | 劣势 | 推荐度 |
|------|--------|--------|------|------|--------|
| **CodeLlama-7B-Instruct** | 7B | 16K | 代码能力强、LoRA 成熟、显存低 | 需微调 | ⭐⭐⭐⭐⭐ |
| Qwen2.5-Coder-7B | 7B | 32K | 中文友好、上下文长 | NL2SQL 案例少 | ⭐⭐⭐⭐ |
| StarCoder2-7B | 7B | 16K | 代码专用 | SQL 能力一般 | ⭐⭐⭐ |
| Llama-3-8B-Instruct | 8B | 8K | 通用能力强 | 需更多 SQL 微调 | ⭐⭐⭐⭐ |
| **Defog-SQLCoder-7B** | 7B | 16K | SQL 专用、SOTA | 需适配中文 | ⭐⭐⭐⭐⭐ |

### 2.2 推荐方案

**✅ 首选：Defog-SQLCoder-7B**
- 理由：专为 NL2SQL 设计，Spider 数据集 SOTA，EX 准确率~85%
- 微调方式：LoRA（r=16, alpha=32）
- 显存需求：单卡 24GB（A10/3090/4090）

**备选：CodeLlama-7B-Instruct**
- 理由：生态成熟、LoRA 工具链完善、中文社区支持好
- 微调方式：LoRA（r=16, alpha=32）
- 显存需求：单卡 24GB

### 2.3 部署方案

| 环境 | 配置 | 推理速度 | 并发 |
|------|------|----------|------|
| **开发** | 1×RTX 4090 (24GB) | ~50 tokens/s | 1 |
| **测试** | 1×A10 (24GB) | ~80 tokens/s | 5 |
| **生产** | 2×A10 (24GB) + vLLM | ~200 tokens/s | 20 |

## 四、微调方法

### 4.1 微调策略对比

| 方法 | 显存 | 训练时间 | 效果 | 推荐场景 |
|------|------|----------|------|----------|
| **Full Fine-tuning** | 80GB+ | 长 | 最优 | 资源充足 |
| **LoRA** | 24GB | 中 | 接近 Full | ✅ 推荐 |
| **QLoRA** | 16GB | 中 | 略低于 LoRA | 资源受限 |
| **Prompt Tuning** | 16GB | 短 | 一般 | 快速验证 |

### 4.2 推荐方案：LoRA 微调

**配置参数：**
```yaml
model: defog/SQLCoder-7B
lora_config:
  r: 16
  alpha: 32
  dropout: 0.1
  target_modules: ["q_proj", "v_proj", "k_proj", "o_proj"]
  
training_config:
  batch_size: 16
  gradient_accumulation: 4
  learning_rate: 2e-4
  epochs: 3
  warmup_ratio: 0.1
  lr_scheduler: cosine
  
hardware:
  gpu: 1×A10 (24GB)
  estimated_time: 8-10 小时
```

```
  77K 条       SQLCoder-7B   r=16      3 epochs   EX/EM    vLLM 服务
```

## 五、评估指标

### 5.1 核心指标

| 指标 | 定义 | 目标 | 测量方式 |
|------|------|------|----------|
| **EX (Execution Accuracy)** | 执行结果正确率 | ≥80% | 对比标准答案执行结果 |
| **EM (Exact Match)** | SQL 完全匹配率 | ≥60% | 字符串精确匹配 |
| **语法正确率** | SQL 可执行比例 | ≥95% | SQLite 语法校验 |
| **响应时间** | 端到端延迟 | <2 秒 | P95 延迟 |

### 5.2 评估数据集

| 数据集 | 用途 | 数量 |

| 财务领域测试集 | 领域适配验证 | 500 条 |
| **总计** | - | **3,068 条** |

### 5.3 评估流程


## 六、技术架构

### 6.1 系统组件

```
┌─────────────────────────────────────────────────────────┐
│                   NL2SQL 引擎                            │
├─────────────────────────────────────────────────────────┤
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │

│  │ 分类器   │  │ SQLCoder │  │ 执行器   │  │ JSON     │ │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │
└─────────────────────────────────────────────────────────┘
```

### 6.2 数据库 Schema

**基于阶段二财报样本设计：**
```sql
-- 核心表
companies (company_id, name, industry, listed_date)
financial_reports (report_id, company_id, period, report_type, publish_date)
income_statements (report_id, revenue, net_profit, gross_profit, ...)
balance_sheets (report_id, total_assets, total_liabilities, ...)
cash_flows (report_id, operating_cf, investing_cf, financing_cf, ...)

-- 索引
CREATE INDEX idx_company_period ON financial_reports(company_id, period);
```

### 6.3 意图分类体系

| 意图类型 | 示例 | SQL 模式 |
|----------|------|----------|
| **单值查询** | "茅台 2024 年营收" | SELECT revenue FROM ... WHERE ... |
| **对比查询** | "茅台 vs 五粮液营收对比" | SELECT ... FROM ... WHERE company IN (...) |
| **趋势查询** | "茅台近 5 年营收趋势" | SELECT period, revenue FROM ... ORDER BY period |
| **聚合查询** | "白酒行业平均毛利率" | SELECT AVG(gross_margin) FROM ... GROUP BY industry |
| **排名查询** | "营收最高的 5 家公司" | SELECT ... ORDER BY revenue DESC LIMIT 5 |
