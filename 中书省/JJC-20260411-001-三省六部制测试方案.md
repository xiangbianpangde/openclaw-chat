## 一、测试目标

验证三省六部制在 OpenClaw 多智能体协作系统中的运行机制是否正常，确保：
1. **中书省**能够正确接收旨意并拟定方案
2. **门下省**能够独立审核方案并提出封驳或审议通过意见
3. **尚书省**能够根据审议通过的方案执行具体任务
4. **太子**能够正确汇总回奏皇上
5. 整个流程的信息传递、状态追踪、看板更新机制畅通无阻

## 二、三省职责定义

### 2.1 中书省 (Zhongshu Secretariat)
- **职责:** 决策起草机构，负责接收皇上旨意，拟定具体方案
- **本次任务:** 设计三省六部制测试方案，定义测试场景和验收标准
- **产出:** 测试方案文档

### 2.2 门下省 (Menxia Chancellery)
- **职责:** 审议封驳机构，负责审核中书省方案，可审议通过或封驳修改
- **本次任务:** 审核中书省提交的测试方案，检查完整性、可行性
- **产出:** 审核意见书 (审议通过/封驳修改)

### 2.3 尚书省 (Shangshu Sheng)
- **职责:** 执行机构，负责根据审议通过的方案具体执行任务
- **本次任务:** 执行测试方案中定义的具体测试任务
- **产出:** 执行报告、测试结果

## 三、测试场景设计

### 场景一：完整流程测试 (主场景)

```
皇上旨意 → 太子整理 → 中书省拟定 → 门下省审核 → 尚书省执行 → 太子回奏 → 皇上审阅
```

**测试步骤:**

| 步骤 | 责任方 | 动作 | 预期结果 |
|------|--------|------|----------|
| 1 | 皇上 | 发布旨意 | 旨意内容明确，有具体目标 |
| 2 | 太子 | 判断消息类型 | 正确识别为旨意而非闲聊 |
| 3 | 太子 | 整理需求、创建任务 | 任务 ID 正确，标题概括准确 |
| 4 | 太子 | 转交中书省 | 中书省收到完整需求 |
| 5 | 中书省 | 拟定方案 | 方案完整、可行、有验收标准 |
| 6 | 中书省 | 提交门下省审核 | 方案文档交付 |
| 7 | 门下省 | 审核方案 | 提出审核意见 (通过/修改) |
| 8 | 尚书省 | 执行任务 | 按方案执行，产出结果 |
| 9 | 尚书省 | 回奏太子 | 提交执行报告 |
| 10 | 太子 | 汇总回奏皇上 | 完整报告交付皇上 |
| 11 | 皇上 | 审阅 | 确认系统运行正常 |

### 场景二：封驳流程测试 (异常场景)

测试门下省封驳权是否有效：

```
中书省拟定 → 门下省封驳 → 中书省修改 → 门下省复审 → 审议通过
```

**测试点:**
- 门下省能否独立提出修改意见
- 中书省是否响应封驳并修改
- 复审流程是否畅通

### 场景三：看板状态追踪测试

测试看板系统是否正确记录全流程：

**检查点:**
- 任务创建时状态正确
- 每次流转都有 flow 记录
- progress 实时更新当前动态
- 完成时 output 和 summary 完整
