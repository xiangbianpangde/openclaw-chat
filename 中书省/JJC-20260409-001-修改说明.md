**4.1 训练数据源**
| 数据源 | 类型 | 数量 | 获取方式 |
|--------|------|------|---------|

    lora_dropout=0.1,

#### 修改项 3：数据安全方案

**门下省意见：**
> 缺少数据安全和隐私保护方案

**修改内容：**

新增 **第五章 数据安全方案** 专章，包含 4 节：

**5.1 传输加密**
- **HTTPS/TLS 配置：** Nginx 前置，TLS 1.2+，HSTS
- **API 鉴权：** JWT Token 认证，24 小时有效期
- **API 限流：** 按角色限流（admin: 1000/min, analyst: 100/min, viewer: 50/min）

**5.2 存储加密**
- **MySQL TDE：** 透明数据加密，敏感字段应用层加密
- **MinIO SSE：** 服务端加密（AES256）
- **字段加密：** 使用 Fernet 对称加密敏感字段

**5.3 访问控制**
- **RBAC 模型：** 4 个预定义角色（admin, analyst, viewer, uploader）
- **权限检查中间件：** `@require_permission()` 装饰器
- **权限表设计：** roles、permissions、role_permissions、user_roles

**5.4 审计日志**
- **操作日志表：** 记录所有 API 操作（用户、动作、资源、IP、时间）
- **查询日志表：** 专门记录数据查询（SQL、自然语言、执行时间）
- **日志查询接口：** `/api/audit/logs` 支持条件查询

**对应文件：**
- `docs/security-config.md` - 安全配置手册

- `src/api/middleware/audit.py` - 审计中间件

#### 修改项 4：风险应对细化

**门下省意见：**
> 部分风险应对措施过于简略，需量化

**修改内容：**

修订 **第十章 风险评估与应对**，量化应对措施：

**风险 1：PDF 解析失败率超过 5%**

**原方案：** "多解析器 fallback、人工校验流程"（过于简略）

**修订后：**
1. **多解析器 fallback：** PyMuPDF → pdfplumber → PyPDF2（3 层降级）
2. **失败样本库：** 自动收集失败样本供分析
3. **人工校验界面：** 提供人工修正工具
4. **自动告警：** 失败率超 5% 自动暂停并通知
5. **错误分类处理：**
   - 文件损坏 → 标记跳过
   - 密码保护 → 加入人工处理队列
   - 格式不支持 → 记录并跳过

**风险 2：NL2SQL 准确率低于 80%**

**原方案：** "规则兜底、人工修正接口"（过于简略）

**修订后：**
1. **规则引擎兜底：** 简单 query 用规则匹配（覆盖率约 30%）
2. **降级方案：** 准确率<80% 时切换为关键词检索
3. **人工修正接口：** 允许用户修正 SQL 并反馈（用于迭代训练）
4. **持续学习：** 收集用户修正数据用于增量训练
5. **准确率监控：** 实时监控 EX/EM 指标，低于阈值告警

**量化指标：**
| 风险项 | 阈值 | 应对措施 | 负责人 |
|--------|------|---------|--------|
| PDF 解析失败率 | >5% | 自动暂停 + 告警 | 后端组 |
| NL2SQL 执行准确率 | <85% | 降级到规则引擎 | 算法组 |
| NL2SQL 精确匹配率 | <75% | 触发增量训练 | 算法组 |
| API P95 延迟 | >2s | 性能优化 + 扩容 | 后端组 |
| 磁盘使用率 | >80% | 清理旧数据 + 扩容 | 运维组 |

**对应文件：**
- `src/core/parse_quality_monitor.py` - 质量监控
- `src/models/nl2sql_fallback.py` - 降级逻辑
- `docs/risk-response-playbook.md` - 风险应对手册

**验收标准：**
- [ ] 失败率监控正常工作
- [ ] 告警通知及时发送
